## Summary
RDD is taught mainly in the Responsibility First phase of craftship. There you learn the three-step RDD design process, create bespoke abstractions on the frontend and backend, and study object stereotypes and stereotypical architecture, then map them to frontend and backend patterns. Khalil says that once you see how these link together, you never see libraries, frameworks and patterns the same way again. RDD skills are also practised in Value First and in the guess point assignments.

## Core ideas
- Main venue: the **Responsibility First** phase.
- Content of that phase:
  1. the **three-step RDD design process**
  2. creating **bespoke abstractions** (frontend and backend)
  3. **object stereotypes**
  4. **stereotypical architecture**, and how it maps to frontend and backend patterns
- Seeing how stereotypes link to the patterns is a "matrix just explodes" moment. After it, libraries, frameworks, tools and patterns all look different.
- RDD is also practised later: in **Value First** and in the **guess point** assignments you'll be asked to use your "responsibility first chops".

## Named frameworks / mental models
- **Three-step RDD process**: design by responsibilities. Steps are not detailed in this lesson.
- **Object stereotypes / stereotypical architecture**: recurring object roles that underlie frontend and backend patterns. Use them to see what frameworks and libraries have in common.
