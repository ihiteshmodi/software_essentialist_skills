## Summary
The way to get better at backend is simple: find a real problem in your life where you want time back, write backend code to solve it, and commit to seeing it through until it actually saves you time. Making it public forces even more learning. The course final project (solo or with a community member) is the intended place to do this. Across the phases of craftship the backend work goes from "just build it" (Code First) to acceptance-tested, Dockerized and pattern-based (Best Practice First), and then to responsibility/role/collaboration-driven design (Responsibility First).

## Core ideas
- Motivation: pick a problem or area where you want to **get back time**, then build backend code there and see it through.
- Making it **public** (usable by others) "is going to propel you".
- The **final project** is the recommended opportunity. It can be done alone or with a community member.
- Backend progression by phase:
  1. **Code First**: just build something. ChatGPT can produce it, "but we need to take it a little bit further".
  2. **Best Practice First**: acceptance test the backend, use a **production-like environment with Docker**, and use a lot of patterns.
  3. **Responsibility First**: think in **responsibilities, roles and collaborations**, do design, and put it into practice in code "guided by objects".
- Expect to do a fair amount of **theoretical work up front**. Use the abstraction prism to know what to do at each point.

## Named frameworks / mental models
- **Get-time-back project selection**: find where you spend time you don't want to, and build code to reclaim it. Use it to pick practice projects that force learning.
- **Abstraction prism**: roadmap for what to do when, from theory to code.
